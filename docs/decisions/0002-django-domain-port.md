# ADR 0002 — 도메인을 Django로 옮기면서 바꾼 것

- 상태: 제안 (2026-11-23)
- 관련: ADR 0001, 2026-11-20 구조 변경 결정 (FastAPI = 추론만, 나머지는 Django + DRF)

## 배경

온톨로지·판정 규칙·검수·조치는 옛 FastAPI 앱(`app/`, SQLAlchemy)에 있다. 구조 변경에 따라 이것을
`backend/apps/inspection`으로 옮긴다. 판정 규칙(`routing`)과 전이표(`transitions`)는 DB를 쓰지 않으므로 그대로 옮기고,
추론이 **비동기**가 되면서 생긴 문제는 아래와 같이 해결한다.

## 결정

1. **Inspection에 처리 상태를 둔다** (`queued → done | failed`).
   접수 API는 행을 먼저 만들고 202를 돌려준다. 판정·크기·엔진 지연은 워커가 채운다.
   추론에 실패한 프레임도 `failed`와 사유로 남는다. 조용히 사라지면 "기록 누락"이 된다.
2. **워커의 재실행에 안전하게 만든다.** Celery는 작업이 끝난 뒤 ack한다(`acks_late`). 그래서 같은 작업이 두 번 올 수 있다.
   `complete_inspection`은 행을 잠그고, `queued`가 아니면 아무것도 하지 않는다.
   감사 샘플 난수도 `(모델 버전, 검사 id)`로 시드를 고정해서, 다시 실행해도 같은 결과가 나온다.
   ReviewTask는 검사당 하나라는 DB 제약을 함께 건다.
3. **서빙 중인 모델과 기록할 버전이 다르면 실패로 남긴다.** 추론 서버가 돌려준 `engine/version`이
   검사의 `ModelVersion(engine, name)`과 다르면 후보를 저장하지 않는다. 다른 버전의 결과가 섞이면 버전 비교가 깨진다.
4. **기준값은 처음 사용된 뒤로 바꿀 수 없다.** 바꾸려면 새 ModelVersion을 등록한다(ADR 0001의 "같은 기준으로 비교").
   운영 버전은 하나만 둔다(부분 유니크 제약). 바꾸는 방법은 관리자 화면의 "운영 모델로 지정" 하나뿐이고, Event로 남는다.
5. **Event에 `lot`을 직접 저장한다.** Lot 이력(#8)이 테이블 다섯 개 조인 대신 `(lot, at)` 인덱스 조회 한 번이 된다.
   Event는 인스턴스 단위로 수정·삭제할 수 없다.
6. **검수자는 User FK, Event.actor는 문자열.** 검수는 로그인한 사람만 하므로 FK로 묶는다.
   Event에는 워커(`system`)와 현장 담당자(계정이 없을 수 있음)도 남아야 하므로 문자열을 쓴다.
7. **감사 샘플의 `confirm` 의미를 고친다.** 옛 코드에서는 감사 샘플에 기준 미만 후보가 있을 때 `confirm`을 누르면
   그 후보가 결함으로 확정됐다. 화면에는 "OK 판정 맞음"이라고 표시되는데 결과는 반대였다. 이제 감사 샘플의 `confirm`은 후보를
   반려하되 재학습 표시는 하지 않는다. `reject`는 허용하지 않는다(docs/ontology.md 표 참고).
8. 운영 기록(Inspection·Defect·ReviewTask·Action·Event)은 관리자 화면에서 **읽기 전용**이다. 상태는 서비스 함수로만 바뀌고,
   서비스 함수가 Event를 함께 쓴다.

## 결과

- 옛 `app/`과 이름이 달라진 필드: `image_uri → image_path`(MEDIA_ROOT 기준 상대 경로), `latency_ms → engine_latency_ms`.
  처리 전체 시간은 `completed_at - received_at`으로 계산한다.
- API(DRF)와 Celery 연결은 다음 PR에서 한다. 이 PR은 모델·migration·서비스·테스트까지만 다룬다.
- 옛 `app/`은 API 이전이 끝나는 PR에서 삭제한다.

## 검토한 대안

- **Inspection을 판정이 끝난 뒤에 만든다**: 202 응답에 돌려줄 id가 없고, 실패한 프레임이 기록되지 않는다.
- **Event 없이 각 테이블의 타임스탬프로 이력을 만든다**: 누가 바꿨는지, 중간 상태(in_progress 등)가 사라진다.
- **기준값을 수정 가능하게 두고 Event로만 남긴다**: 과거 검사가 어떤 기준으로 판정됐는지 다시 계산해야 하고, 실수로 바꾸기 쉽다.
