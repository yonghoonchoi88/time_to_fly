# Defect-to-Action

> 결함을 **찾는 것**에서 끝나지 않고, **기록 → 담당자 검수 → 현장 조치 → 재발 분석**까지 이어지는 검사 운영 시스템

🚧 **v0.1 — 개발 중.** 아래 수치·화면은 측정이 끝난 뒤 채웁니다.

## 왜 만드나

검사 AI의 정확도가 높아도, 결과가 사람의 판단과 조치로 이어지지 않으면 현장에서 아무것도 바뀌지 않습니다.
이 프로젝트는 검출 이후의 운영 흐름을 다룹니다.

## 흐름

```
카메라 / 라인 재생 ─▶ 검사 엔진 ─▶ 판정(OK·NG·REVIEW) ─▶ DB 기록
                                       │
                         REVIEW / 감사 샘플 ─▶ 검수 대기열 ─▶ 승인 · 반려 · 놓침 추가
                                       │
                                  NG 확정 ─▶ 조치(Lot 격리 · 재검 · 라인 정지) ─▶ 완료
                                                                   │
                                                     이력 · 재발 분석 · 운영 지표
```

- **검사 엔진은 교체 가능**: 엔진은 결함 후보만 돌려주고, 판정 규칙은 엔진 밖에 있습니다.
- **샘플링 감사**: 모델이 놓친 결함은 후보로 뜨지 않으므로, OK 판정 일부를 사람이 다시 봅니다.
- 데이터 구조: [docs/ontology.md](docs/ontology.md)

## 실행

```bash
cp .env.example .env
docker compose up --build
curl localhost:8000/health
```

테스트:

```bash
pip install -r requirements-dev.txt
pytest -q
```
